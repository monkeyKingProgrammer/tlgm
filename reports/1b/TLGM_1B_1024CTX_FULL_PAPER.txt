======================================================================
ABSTRACT
======================================================================

TLGM-1B-1024 is a decoder-only autoregressive language model with exactly
1,015,592,960 unique trainable parameters and a maximum context length of
1,024 tokens. TLGM means Token-Local Global-Mixing. It is an experimental
alternative to a Transformer. It does not contain self-attention, query,
key, or value projections, an attention softmax, a recurrent state, a
convolution, a state-space block, or a key-value cache.

The model represents text with an 8,192-entry byte-level byte-pair encoding
(BPE) tokenizer. Input token and absolute-position embeddings have width
2,048. A shared per-token encoder first transforms every token independently.
Twenty-seven global mixing blocks then alternate between:

  1. causal global mixing over sequence positions using learned
     lower-triangular 1,024 by 1,024 matrices; and
  2. nonlinear per-position feature mixing using 2,048 -> 8,192 -> 2,048
     multilayer perceptrons.

Residual connections and pre-normalization are used in both branches. A final
LayerNorm feeds an output projection tied to the input token embedding.
Standard one-token causal cross entropy trains position t to predict token
t+1.

The model is being trained entirely from random initialization. It does not
use MiniMind, GPT, Llama, Qwen, or any other pretrained weights. Its
pretraining stream contains exactly 20 billion project-tokenizer tokens from
educational web text, synthetic educational material, English Wikipedia, and
FineWeb-Edu. The pretraining schedule processes approximately 20 billion seen
tokens. Three supervised fine-tuning stages are configured to follow
pretraining automatically.

At the status snapshot shown in this paper, the corrected production run had
processed 993,918,976 tokens at 23,923 tokens per second on one NVIDIA RTX PRO
6000 Blackwell Workstation Edition. The latest held-out loss was 3.27324 with
perplexity 26.3968 at step 15,000. Pretraining was approximately 4.97 percent
complete, with an estimated completion time of 2026-08-06 12:29 UTC+08:00.

This document is intended to be sufficient for an engineer to recreate the
architecture, tokenizer procedure, data pipeline, optimizer, checkpoint
contract, supervised fine-tuning, inference loop, and single-GPU deployment
without needing the original source repository.

1.2 Intended purpose
--------------------

TLGM-1B-1024 is a research and learning model. It is intended to test whether
fixed learned causal sequence-mixing matrices, combined with large per-token
feature MLPs, can learn useful language behavior without content-dependent
self-attention.

The post-trained model is intended to support:

  - short interactive conversation;
  - short factual responses within learned knowledge;
  - basic descriptions and explanations;
  - elementary arithmetic patterns represented in SFT;
  - short story generation;
  - simple uncertainty responses;
  - continuation and generation within a 1,024-token window.


1.3 Out-of-scope uses
---------------------

The model is not designed or validated for:

  - medical, legal, financial, or safety-critical advice;
  - autonomous control;
  - high-confidence factual research;
  - secure code generation;
  - long-document reasoning beyond 1,024 tokens;
  - multilingual parity;
  - private or confidential data processing without separate controls;
  - matching a commercial 1B or larger Transformer solely from parameter
    count.

1.5 Expected limitations
------------------------

The final model will have important limitations:

  - A 1B-parameter model is small by current general-purpose LLM standards.
  - Twenty billion pretraining tokens are serious for this experiment but
    far below the data budgets of major production models.
  - Sequence routing is learned by position, not selected dynamically from
    token content as in attention.
  - The model cannot natively extrapolate beyond its trained 1,024 absolute
    positions.
  - Autoregressive decoding recomputes the retained context for each token.
  - No KV cache is available.
  - Knowledge can be incomplete, outdated, or incorrect.
  - SFT can improve response style but cannot create knowledge absent from
    pretraining.
  - Repeated targeted SFT examples can produce memorization or answer
    substitution if weighted too strongly.
  - Dataset source material can contain biases, errors, or undesirable text.


1.6 Safety and data statement
-----------------------------

This experiment uses public datasets identified later in this paper. Anyone

======================================================================
2. DESIGN GOALS AND NON-GOALS
======================================================================

2.1 Design goals
----------------

The architecture was built around six goals:

  1. Train a complete autoregressive language model from scratch.
  2. Avoid Transformer self-attention and all QKV projections.
  3. Preserve strict left-to-right causality.
  4. Give every position access to all earlier positions in every global
     block.
  5. Keep implementation simple enough to inspect and reproduce.
  6. Fit training on one large workstation GPU.


2.2 Explicit non-components
---------------------------

TLGM-1B-1024 contains none of the following:

  - multi-head attention;
  - grouped-query attention;
  - multi-query attention;
  - query, key, and value tensors;
  - rotary position embeddings;
  - ALiBi;
  - an attention mask applied to attention scores;
  - an attention softmax;
  - a Transformer decoder block;
  - an RNN, LSTM, or GRU;
  - a convolutional sequence layer;
  - Mamba or another selective state-space layer;
  - mixture-of-experts routing;
  - retrieval augmentation;
  - a key-value cache.


2.3 Core architectural idea
---------------------------

The architecture separates two forms of processing:

  Token-local feature processing:
    Dense MLPs transform the 2,048 features at each position. These weights
    are shared over positions but are different between blocks.

  Global causal position processing:
    A learned lower-triangular matrix mixes all earlier sequence positions
    into each current position. The same position matrix is applied to every
    feature channel.

This is why the architecture is called Token-Local Global-Mixing.

======================================================================
4. TOKENIZATION
======================================================================

4.1 Tokenizer type
------------------

The tokenizer is a ByteLevelBPETokenizer implemented with the Hugging Face
"tokenizers" library.

Byte-level tokenization first represents text through a reversible byte
alphabet. BPE training then repeatedly merges frequent adjacent symbols until
the requested vocabulary size is reached. This has two useful properties:

  - arbitrary input bytes can be represented;
  - normal text can use multi-byte and multi-character subword tokens.

The model does not use the tokenizer or vocabulary of another pretrained
language model.

The tokenizer constructor uses these exact options:

  add_prefix_space:              false
  lowercase:                     false
  dropout:                       none
  unicode_normalizer:            none
  continuing_subword_prefix:     none
  end_of_word_suffix:            none
  trim_offsets:                  false


4.2 Vocabulary and special tokens
---------------------------------

Requested and observed vocabulary size:
  8192

Minimum BPE merge frequency:
  2

Special tokens are registered in this exact order:

  ID 0: <pad>
  ID 1: <bos>
  ID 2: <eos>
  ID 3: <unk>

These IDs must remain unchanged in every config, dataset, checkpoint, and
inference program.


4.3 Tokenizer training corpus
-----------------------------

The tokenizer-training utility constructs a temporary UTF-8 text file from
up to 200,000 JSONL records. Each record must contain a "text" field. Embedded
newlines are replaced with spaces and each source document is written as one
line.

The default source directory is an earlier public-text preparation containing
the following document categories:

  - SmolLM fineweb-edu-dedup;
  - SmolLM cosmopedia-v2;
  - English Wikipedia 20231101.en;
  - TinyStories;
  - FineWeb sample-10BT;
  - codeparrot/github-code-clean.

That earlier document pool used a 40/20/15/10/10/5 percent selection target.
The BPE tokenizer itself is trained from scratch over extracted text. No
pretrained token IDs or embedding weights are imported.


4.4 Normative tokenizer construction
-------------------------------------

Equivalent Python:

  from tokenizers import ByteLevelBPETokenizer

  special = ["<pad>", "<bos>", "<eos>", "<unk>"]
  tokenizer = ByteLevelBPETokenizer()
  tokenizer.train(
      files=["tokenizer_train.txt"],
      vocab_size=8192,
      min_frequency=2,
      special_tokens=special,
  )
  tokenizer.save_model("tokenizer")

This writes:

  tokenizer/vocab.json
  tokenizer/merges.txt

The observed files in the current experiment are approximately:

  vocab.json:  116,374 bytes
  merges.txt:   67,380 bytes

SHA-256:

  vocab.json:
    E4C5DADFA59E1059324269132827F4C548F3411C5409A90BDD0FEF0212A119D3

  merges.txt:
    4FF5482BA80A329A4F5FB50E5179460F3C97FE7DFE814AB4C0EB8C1183EADCE4

For bit-for-bit checkpoint compatibility, the exact same vocab.json and
merges.txt must be used. Training a new tokenizer by the same method creates
an equivalent architecture but not necessarily token-ID-compatible
checkpoints.


4.5 Document and chat boundaries
--------------------------------

Pretraining documents are encoded as:

  [<bos>] + BPE(document_text) + [<eos>]

SFT conversations are encoded as:

  <bos>
  User: user text
  Assistant: assistant text
  <eos>

The literal role strings and newlines are normal text processed by BPE.

6. END-TO-END MODEL GRAPH
======================================================================

The complete forward graph is:

  input token IDs [B,N]
            |
            +-----------------------------+
            |                             |
            v                             v
  token embedding [V,D]       position embedding [C,D]
            |                             |
            +------------ addition -------+
                          |
                    dropout, p=0
                          |
              shared token-local encoder
             Linear 2048 -> 8192
             GELU
             dropout, p=0
             Linear 8192 -> 2048
             LayerNorm 2048
                          |
            +-------------+-------------+
            | Global Mixing Block 1     |
            +---------------------------+
                          |
                         ...
                          |
            +---------------------------+
            | Global Mixing Block 27    |
            +-------------+-------------+
                          |
                 final LayerNorm 2048
                          |
            tied embedding output projection
                     2048 -> 8192
                          |
                logits [B,N,8192]

Every global block has two residual sublayers:

  A. token/position mixing:

     x
     |
     LayerNorm
     |
     CausalSequenceLinear 1024
     |
     GELU
     |
     CausalSequenceLinear 1024
     |
     + residual x

  B. feature mixing:

     x_after_token_mix
     |
     LayerNorm
     |
     Linear 2048 -> 8192
     |
     GELU
     |
     Dropout(0)
     |
     Linear 8192 -> 2048
     |
     Dropout(0)
     |
     + residual x_after_token_mix

7. EMBEDDING LAYER
======================================================================

7.1 Learned tensors
-------------------

Token embedding:
  shape [8192, 2048]

Position embedding:
  shape [1024, 2048]


7.2 Forward operation
---------------------

For token ID T[b,n]:

  X_embed[b,n,d] =
      E_token[T[b,n],d] + E_position[n,d]

The position vector is generated as:

  positions = [0, 1, ..., N-1]

The summed embedding passes through Dropout with probability zero. The
dropout module remains in the graph but has no numerical effect under the
current config.


7.3 Parameters
--------------

Token embedding:

  8192 * 2048 = 16,777,216

Position embedding:

  1024 * 2048 = 2,097,152

Total embedding parameters:

  18,874,368


======================================================================
8. SHARED TOKEN-LOCAL ENCODER
======================================================================

8.1 Purpose
-----------

This module performs a nonlinear transformation at each token position before
global sequence mixing begins. It does not communicate between positions.
The same encoder parameters are shared over all positions and all examples.


8.2 Operation
-------------

For every [b,n] independently:

  A = W1 X_embed + b1
  B = GELU(A)
  C = W2 B + b2
  X0 = LayerNorm(C)

Shapes:

  W1: [8192, 2048]
  b1: [8192]
  W2: [2048, 8192]
  b2: [2048]
  LayerNorm scale: [2048]
  LayerNorm bias:  [2048]


8.3 Parameters
--------------

  first weight:    2048 * 8192 = 16,777,216
  first bias:                         8,192
  second weight:   8192 * 2048 = 16,777,216
  second bias:                        2,048
  LayerNorm:       2 * 2048 =         4,096
  total:                         33,568,768


======================================================================
9. CAUSAL SEQUENCE LINEAR OPERATOR
======================================================================

9.1 Learned state
-----------------

One CausalSequenceLinear layer has:

  weight W: [1024, 1024]
  bias b:   [1024]

It also constructs a non-trainable lower-triangular mask M:

  M[n,j] = 1 if j <= n
           0 if j > n

M is a deterministic, non-persistent buffer. It is reconstructed with the
model and is not saved in checkpoints.


9.2 Runtime slicing
-------------------

For a runtime length N <= 1024:

  A = W[0:N,0:N] elementwise-multiplied by M[0:N,0:N]
  c = b[0:N]


9.3 Forward equation
--------------------

Input X and output Y both have shape [B,N,D].

  Y[b,n,d] = c[n] + sum over j=0..n of A[n,j] X[b,j,d]

Equivalent einsum:

  Y = einsum("bjd,nj->bnd", X, A) + c[None,:,None]

The same A is used for every batch item and every feature channel.


9.4 Causality
-------------

Because A[n,j] is exactly zero for j > n, output position n cannot depend on
future input positions. Composition with position-wise LayerNorm, GELU,
feature MLPs, and residual additions preserves this property. Therefore every
network output at position n is a function only of tokens at positions
0 through n.


9.5 Difference from attention
-----------------------------

Attention computes content-dependent routing coefficients from Q and K
features. This operator instead learns one fixed routing matrix per layer:

  - coefficients depend on source and destination positions;
  - coefficients do not depend on current token content;
  - all feature channels share the same position routing;
  - there is no softmax normalization;
  - there are no attention heads.

Content still affects hidden values and all nonlinear feature processing, but
it does not dynamically alter the sequence-routing coefficients.


9.6 Parameter count
-------------------

One operator:

  1024 * 1024 + 1024 = 1,049,600

Two per global block:

  2,099,200

Fifty-four across 27 blocks:

  56,678,400


======================================================================
10. GLOBAL MIXING BLOCK
======================================================================

10.1 Token-mixing branch
------------------------

Given block input X:

  U = TokenLayerNorm(X)
  P = TokenMix1(U)
  Q = GELU(P)
  R = TokenMix2(Q)
  X_token = X + R

TokenMix1 and TokenMix2 are independent CausalSequenceLinear modules.


10.2 Feature-mixing branch
--------------------------

  S = FeatureLayerNorm(X_token)
  T = W3 S + b3
  U = GELU(T)
  V = Dropout(U, p=0)
  Z = W4 V + b4
  Z = Dropout(Z, p=0)
  Y = X_token + Z

Shapes:

  W3: [8192, 2048]
  b3: [8192]
  W4: [2048, 8192]
  b4: [2048]


10.3 Per-block parameters
-------------------------

Two sequence operators:

  2 * (1024*1024 + 1024) = 2,099,200

Feature MLP:

  2048*8192 + 8192 + 8192*2048 + 2048
  = 33,564,672

Two LayerNorms:

  2 norms * (2048 scale + 2048 bias)
  = 8,192

Total per block:

  2,099,200 + 33,564,672 + 8,192
  = 35,672,064


10.4 Block stack
----------------

There are exactly 27 blocks:

  X1  = Block1(X0)
  X2  = Block2(X1)
  ...
  X27 = Block27(X26)

All blocks have identical dimensions but independent trainable parameters.
No weights are shared between block numbers.

Total stack parameters:

  35,672,064 * 27 = 963,145,728


======================================================================
11. FINAL NORMALIZATION AND LANGUAGE-MODEL HEAD
======================================================================

The block-stack output is normalized:

  Z = FinalLayerNorm(X27)

The final LayerNorm contains:

  scale [2048]
  bias  [2048]

for 4,096 parameters.

The vocabulary projection is:

  Logits[b,n,v] = sum over d of Z[b,n,d] E_token[v,d]

The output head's weight object is tied to the token-embedding matrix. It does
not allocate a second [8192,2048] matrix. Gradients from input embedding use
and output prediction update the same tensor.

There is no vocabulary-output bias.

13. INITIALIZATION
======================================================================

13.1 General initialization
---------------------------

All training starts from random weights.

  Linear weights:
    Normal(mean=0, standard deviation=0.02)

  Embedding weights:
    Normal(mean=0, standard deviation=0.02)

  Linear biases:
    zero

  LayerNorm scales:
    one

  LayerNorm biases:
    zero


13.2 Residual-depth scaling
---------------------------

Residual output projections receive depth-aware initialization.

Let L=27. Define:

  residual_gain = 1 / sqrt(2L)
                = 1 / sqrt(54)
                approximately 0.13608276

For each global block:

  TokenMix1 weight:
    Xavier uniform with gain 1

  TokenMix2 weight:
    Xavier uniform with gain residual_gain

  feature MLP second/output weight:
    Normal(
      mean=0,
      standard deviation=0.02 / sqrt(54)
    )

The second feature weight's standard deviation is approximately:

  0.00272166

This reduces the initial contribution of each residual branch as network depth
increases.


13.3 Random seed
----------------

The pretraining seed is 1001. At process startup the implementation seeds:

  - Python random;
  - NumPy;
  - PyTorch CPU;
  - every visible CUDA device.

Exact deterministic replay across different GPU architectures or PyTorch
versions is not guaranteed, but checkpoint resume restores all captured RNG
states on the same software/hardware stack.


======================================================================
14. LANGUAGE-MODEL OBJECTIVE
======================================================================

14.1 Pretraining samples
------------------------

Each dataset item contains exactly 1,024 consecutive token IDs:

  input_ids = [t0, t1, ..., t1023]
  labels    = a clone of input_ids


14.2 Single causal shift
------------------------

The model computes:

  prediction logits:
    logits[:, 0:1023, :]

  targets:
    labels[:, 1:1024]

Then:

  loss = CrossEntropy(
      flatten(logits[:, :-1, :]),
      flatten(labels[:, 1:]),
      ignore_index=-100
  )

Cross-entropy uses:

  class weights:     none
  reduction:         mean
  label smoothing:   0.0

The exact prediction relation is:

  hidden position 0 predicts token t1
  hidden position 1 predicts token t2
  ...
  hidden position 1022 predicts token t1023

Position 1023 has no next token inside the same window and contributes no
training target.

Each full pretraining sequence therefore contains:

  1,024 seen tokens
  1,023 supervised next-token targets


14.3 SFT masking
----------------

The same model-level shift is used for SFT. Labels are set to -100 for:

  - <bos>;
  - system and user text;
  - role prefixes;
  - padding;
  - the first retained token after truncation.

Only assistant-answer tokens and the terminal <eos> token contribute to SFT
cross entropy.

15.4 Streaming preparation algorithm
-------------------------------------

For each source in the listed order:

  1. Open its training split with Hugging Face datasets in streaming mode.
  2. Read the configured "text" field.
  3. If "text" is unavailable, try "content", "article", then "body".
  4. Trim whitespace.
  5. Reject text shorter than 80 characters.
  6. Encode:

       [<bos>] + tokenizer.encode(text).ids + [<eos>]

  7. If the document crosses the source quota, truncate its final token list
     exactly at the quota.
  8. Write token IDs into a preallocated uint16 memory map.
  9. Stop the source when its exact token quota is reached.
 10. Continue with the next source.

The output is a concatenated token stream, not one separate file per source.


15.5 Resume behavior during data preparation
--------------------------------------------

The builder writes progress metadata containing:

  - number of tokens already written;
  - total target;
  - output path;
  - source quotas and source progress.

When restarted, it:

  - opens the existing full-size memory map in read/write mode;
  - skips complete sources;
  - replays rows in the interrupted source until reaching the saved token
    offset;
  - resumes writing from that offset.

Completion metadata is written atomically. The first three source row counts
are null in the final current metadata because those sources were already
complete when the final resumed metadata was constructed. Their exact token
counts are known and validated; their original row counts were not retained.
The fourth source records 227,370 rows used.


15.6 Integrity validation
-------------------------

Before training, validate:

  metadata tokens == 20,000,000,000
  metadata target_tokens == 20,000,000,000
  sum(source written_tokens) == 20,000,000,000
  binary byte size == 40,000,000,000
  dtype == uint16

Training also performs its own metadata and byte-size checks before building
the model.

16. PRETRAINING DATASET AND SAMPLER
======================================================================

16.1 Window construction
------------------------

The uint16 stream is split into non-overlapping windows:

  start = index * 1024
  end   = start + 1024

The number of complete windows is:

  floor(20,000,000,000 / 1024)
  = 19,531,250

No extra next token is read by the dataset because the model performs the
causal shift inside each 1,024-token window.


16.2 Validation split
---------------------

The final 10,000 windows are held out:

  total complete windows:    19,531,250
  validation windows:            10,000
  training windows:          19,521,250

The split is deterministic and contiguous in dataset-index space.


16.3 Constant-memory random sampler
-----------------------------------

Allocating a Python random permutation for more than 19 million samples is
unnecessarily expensive. The sampler instead uses an affine permutation.

For dataset size S:

  choose multiplier a such that gcd(a,S)=1
  choose offset b in [0,S)

Then:

  sample_index(p) = (a*p + b) mod S

for p from 0 through S-1.

Because a is coprime with S, this mapping is bijective. Every sample appears
exactly once per sampler epoch.

The sampler stores:

  seed
  epoch
  offset

The epoch-specific random generator seed is:

  base_seed + epoch

This provides randomized traversal, deterministic reconstruction, constant
sampler memory, and resumable position.

The training DataLoader uses:

  sampler:       ResumableRandomSampler
  shuffle:       false because the sampler owns ordering
  drop_last:     true
  pin_memory:    true on CUDA
  num_workers:   0

The validation DataLoader uses:

  shuffle:       false
  drop_last:     false
  pin_memory:    true on CUDA
  num_workers:   0

17.3 Optimizer
--------------

Use AdamW over all trainable parameters:

      model.parameters(),
      lr=1.5e-4,

  )

The remaining AdamW values are PyTorch defaults:

  beta1:          0.9
  beta2:          0.999
  epsilon:        1e-8

  maximize:       false
  capturable:     false
  differentiable: false

The foreach and fused choices are left as `None`, allowing PyTorch to select

PyTorch and CUDA versions listed in this paper.


17.4 Learning-rate schedule
---------------------------

Let:

  s = current optimizer step, starting at 1
  S = 305176
  W = 3000
  eta = 0.00015

Warmup:

  if s <= W:
      lr = eta * s / W

Cosine phase:

  progress = min((s-W)/(S-W), 1)

  lr = eta * (
      0.1 + 0.45 * (1 + cos(pi * progress))
  )

The schedule reaches eta at the end of warmup and approaches 0.1*eta at the
last step.


17.5 Mixed precision and accumulation
-------------------------------------

For each optimizer step:

  1. Set all gradients to None.
  2. Repeat eight times:
       a. load one microbatch;
       b. transfer input IDs and labels to CUDA;
       c. enter CUDA FP16 autocast;
       d. compute model loss;
       e. divide loss by 8;
       f. verify the divided loss is finite;
       g. scale the loss with torch.amp.GradScaler;
       h. backpropagate;
       i. accumulate unscaled logging loss and token counters.
  3. If any microbatch loss is non-finite:
       a. discard the complete accumulated gradient;
       b. reduce the scaler;
       c. do not advance global step;
       d. retry.
  4. Advance global step.
  5. Calculate and set the current learning rate.
  6. Unscale gradients.
  7. Clip global gradient norm to 1.0.
  8. Execute optimizer step through the scaler.
  9. Update the scaler.
 10. Synchronize CUDA for accurate elapsed-time accounting.
 11. Append a JSONL training record.
 12. Run validation and save when scheduled.

19.4 Resume algorithm
---------------------

At process startup:

  1. Construct the configured model.
  2. Construct AdamW and GradScaler.
  3. If the stage's own checkpoint exists:
       a. load model state strictly;
       b. load optimizer state;
       c. load scaler state;
       d. recover global step and counters;
       e. recover sampler state;
       f. recover all RNG states.
  4. Construct the sampler and apply its saved state.
  5. Construct the DataLoader.
  6. Restore RNG states.
  7. Continue until max_steps.

For an SFT stage whose own checkpoint does not exist, load only model weights
from its configured initialization checkpoint and begin that SFT stage at
step zero with a new optimizer and schedule.


19.5 Shutdown and restart
-------------------------

The Linux service sends SIGINT when stopping and permits up to ten minutes for
shutdown. The production service uses Restart=on-failure with a 30-second
delay. The service is enabled at boot.

Because checkpoints are written every 500 steps, an unexpected stop can lose
at most the work after the most recently completed checkpoint. The checkpoint
itself remains valid because replacement is atomic.

  append answer to input_ids

======================================================================
22. AUTOREGRESSIVE GENERATION
======================================================================

22.1 Prompt construction
------------------------

Single-turn prompt:

  User: <user text>
  Assistant:

The model input is:

  [<bos>] + BPE(prompt)

For history, append complete earlier turns:

  User: earlier question
  Assistant: earlier answer
  User: current question
  Assistant:


22.2 Generation loop
--------------------

Repeat up to max_new_tokens:

  1. Retain:

       context = input_ids[:, -1024:]

  2. Run the full model over context.
  3. Select final-position logits:

       next_logits = logits[:, -1, :]

  4. If temperature <= 0:

       next_id = argmax(next_logits)

     Otherwise:

       next_logits = next_logits / temperature
       apply top-k
       apply top-p
       next_id = multinomial(softmax(next_logits))

  5. Append next_id to input_ids.
  6. Stop if next_id == eos_id.


22.3 Top-k filtering
--------------------

Keep the k highest logits and set all lower logits to negative infinity. If
k is zero, disable top-k filtering.


22.4 Top-p filtering
--------------------

  1. Sort logits descending.
  2. Softmax sorted logits.
  3. Compute cumulative probabilities.
  4. Remove tokens after cumulative probability first exceeds p.
  5. Always retain at least the highest-probability token.
  6. Scatter filtered values back to original vocabulary order.


22.5 Stop cleanup
-----------------

After decoding newly generated IDs, stop displayed text at the first:

  <eos>
  <pad>
  <bos>
  User:

Then trim whitespace.


22.6 Recommended chat settings
------------------------------

Conservative factual/simple chat:

  temperature:     0.3
  top_p:           0.8
  top_k:           20
  max_new_tokens:  120 to 180

More varied creative output:

  temperature:     0.7
  top_p:           0.9
  top_k:           50


======================================================================
23. COMPUTATIONAL CHARACTERISTICS
======================================================================

23.1 Sequence mixing complexity
-------------------------------

One sequence operator applies an N by N matrix to D feature channels:

  O(B * D * N^2)

There are two per block and 27 blocks:

  O(2 * L * B * D * N^2)


23.2 Feature mixing complexity
------------------------------

Two dense projections per block cost:

  O(2 * B * N * D * H)

With D=2048 and H=8192, feature MLPs dominate parameter count and a large
fraction of compute.


23.3 Prefill
------------

The prompt is processed in parallel over positions. TLGM does not allocate
multi-head attention score tensors and does not build a KV cache. It still
performs dense position mixing in every block.


23.4 Decoding
-------------

The present implementation has no incremental sequence state. Every generated
token runs the model again over the retained context. This makes long
autoregressive generation less efficient than an optimized Transformer with
a KV cache.


23.5 Context scaling
--------------------

Increasing context from C to 2C:

  - doubles position-embedding parameters;
  - quadruples each sequence-matrix parameter count;
  - approximately quadruples sequence-mixing compute at full context;
  - requires newly initialized matrix regions and further training;
  - is not a config-only inference change.

24.2 Causal sequence operator
----------------------------------------------------------------------

  import torch
  from torch import nn

  class CausalSequenceLinear(nn.Module):
      def __init__(self, sequence_length):
          super().__init__()
          self.sequence_length = sequence_length
          self.weight = nn.Parameter(
              torch.empty(sequence_length, sequence_length)
          )
          self.bias = nn.Parameter(torch.zeros(sequence_length))
          self.register_buffer(
              "causal_mask",
              torch.tril(torch.ones(sequence_length, sequence_length)),
              persistent=False,
          )
          nn.init.xavier_uniform_(self.weight)

      def forward(self, x):
          if x.ndim != 3:
              raise ValueError("expected [B,N,D]")
          n = x.shape[1]
          if n > self.sequence_length:
              raise ValueError("sequence exceeds configured context")
          a = (
              self.weight[:n, :n]
              * self.causal_mask[:n, :n]
          )
          b = self.bias[:n]
          y = torch.einsum("bjd,nj->bnd", x, a)
          return y + b.view(1, n, 1)

24.3 Embeddings and shared encoder
----------------------------------------------------------------------

  class TokenPositionEmbeddings(nn.Module):
      def __init__(self, cfg):
          super().__init__()
          self.token_embedding = nn.Embedding(
              cfg.vocab_size, cfg.embed_dim
          )
          self.position_embedding = nn.Embedding(
              cfg.context_length, cfg.embed_dim
          )
          self.dropout = nn.Dropout(cfg.dropout)

      def forward(self, input_ids):
          b, n = input_ids.shape
          pos = torch.arange(
              n, device=input_ids.device
          ).unsqueeze(0).expand(b, n)
          return self.dropout(
              self.token_embedding(input_ids)
              + self.position_embedding(pos)
          )

  class SharedTokenEncoder(nn.Module):
      def __init__(self, cfg):
          super().__init__()
          self.net = nn.Sequential(
              nn.Linear(cfg.model_dim, cfg.local_hidden_dim),
              nn.GELU(),
              nn.Dropout(cfg.dropout),
              nn.Linear(cfg.local_hidden_dim, cfg.model_dim),
              nn.LayerNorm(cfg.model_dim),
          )

      def forward(self, x):
          return self.net(x)

24.4 Global block
----------------------------------------------------------------------

  class GlobalMixingBlock(nn.Module):
      def __init__(self, cfg):
          super().__init__()
          self.token_norm = nn.LayerNorm(cfg.model_dim)
          self.token_mix_1 = CausalSequenceLinear(
              cfg.context_length
          )
          self.token_mix_2 = CausalSequenceLinear(
              cfg.context_length
          )
          self.feature_norm = nn.LayerNorm(cfg.model_dim)
          self.feature_mlp = nn.Sequential(
              nn.Linear(cfg.model_dim, cfg.feature_hidden_dim),
              nn.GELU(),
              nn.Dropout(cfg.dropout),
              nn.Linear(cfg.feature_hidden_dim, cfg.model_dim),
              nn.Dropout(cfg.dropout),
          )
          self.act = nn.GELU()

      def forward(self, x):
          y = self.token_norm(x)
          y = self.token_mix_1(y)
          y = self.act(y)
          y = self.token_mix_2(y)
          x = x + y
          y = self.feature_mlp(self.feature_norm(x))
          return x + y

24.5 Complete language model
----------------------------------------------------------------------

  import math
  import torch.nn.functional as F

  class TLGMForCausalLM(nn.Module):
      def __init__(self, cfg):
          super().__init__()
          self.config = cfg
          self.embeddings = TokenPositionEmbeddings(cfg)
          self.input_projection = (
              nn.Identity()
              if cfg.embed_dim == cfg.model_dim
              else nn.Linear(cfg.embed_dim, cfg.model_dim)
          )
          self.shared_encoder = SharedTokenEncoder(cfg)
          self.blocks = nn.ModuleList([
              GlobalMixingBlock(cfg)
              for _ in range(cfg.num_global_blocks)
          ])
          self.final_norm = nn.LayerNorm(cfg.model_dim)
          self.lm_head = nn.Linear(
              cfg.model_dim, cfg.vocab_size, bias=False
          )
          if cfg.tie_embeddings and cfg.embed_dim == cfg.model_dim:
              self.lm_head.weight = (
                  self.embeddings.token_embedding.weight
              )
          self.apply(self._init_weights)
          self._scale_residual_outputs()

      def _init_weights(self, module):
          if isinstance(module, (nn.Linear, nn.Embedding)):
              nn.init.normal_(
                  module.weight,
                  mean=0.0,
                  std=self.config.initializer_range,
              )
              if (
                  isinstance(module, nn.Linear)
                  and module.bias is not None
              ):
                  nn.init.zeros_(module.bias)
          elif isinstance(module, nn.LayerNorm):
              nn.init.ones_(module.weight)
              nn.init.zeros_(module.bias)

      def _scale_residual_outputs(self):
          l = self.config.num_global_blocks
          gain = 1.0 / math.sqrt(2*l)
          for block in self.blocks:
              nn.init.xavier_uniform_(
                  block.token_mix_1.weight
              )
              nn.init.xavier_uniform_(
                  block.token_mix_2.weight,
                  gain=gain,
              )
              nn.init.normal_(
                  block.feature_mlp[3].weight,
                  mean=0.0,
                  std=(
                      self.config.initializer_range
                      / math.sqrt(2*l)
                  ),
              )

      def forward(self, input_ids, labels=None):
          x = self.embeddings(input_ids)
          x = self.input_projection(x)
          x = self.shared_encoder(x)
          for block in self.blocks:
              x = block(x)
          logits = self.lm_head(self.final_norm(x))
          loss = None
          if labels is not None:
              loss = F.cross_entropy(
                  logits[:, :-1].contiguous().view(
                      -1, logits.size(-1)
                  ),
                  labels[:, 1:].contiguous().view(-1),
                  ignore_index=-100,
              )
          return {"logits": logits, "loss": loss}

  import numpy as np
  import torch
  from torch.utils.data import Dataset

  class TokenBinDataset(Dataset):
      def __init__(self, path, context_length=1024):
          self.context_length = context_length
          self.tokens = np.memmap(
              path, dtype=np.uint16, mode="r"
          )

      def __len__(self):
          return len(self.tokens) // self.context_length

      def __getitem__(self, index):
          start = index * self.context_length
          end = start + self.context_length
          chunk = np.asarray(
              self.tokens[start:end],
              dtype=np.int64,
          )
          input_ids = torch.from_numpy(chunk).long()
          labels = input_ids.clone()
          return input_ids, labels

24.7 Training-loop essentials
----------------------------------------------------------------------

  model = TLGMForCausalLM(Config()).to("cuda")
  optimizer = torch.optim.AdamW(
      model.parameters(),
      lr=1.5e-4,
      weight_decay=0.1,
  )
  scaler = torch.amp.GradScaler("cuda", enabled=True)

  for global_step in range(start_step, 305176):
      optimizer.zero_grad(set_to_none=True)
      valid = True

      for microstep in range(8):
          input_ids, labels = next_batch()
          input_ids = input_ids.cuda(non_blocking=True)
          labels = labels.cuda(non_blocking=True)

          with torch.amp.autocast(
              "cuda", dtype=torch.float16
          ):
              loss = model(input_ids, labels)["loss"] / 8

          if not torch.isfinite(loss):
              valid = False
              break

          scaler.scale(loss).backward()

      if not valid:
          optimizer.zero_grad(set_to_none=True)
          scaler.update(
              new_scale=max(scaler.get_scale()/2, 1)
          )
          continue

      set_cosine_lr(optimizer, global_step+1)
      scaler.unscale_(optimizer)
      torch.nn.utils.clip_grad_norm_(
          model.parameters(), 1.0
      )
      scaler.step(optimizer)
      scaler.update()

30.2 Causality test
-------------------

Construct two sequences A and B:

  - positions 0 through k are identical;
  - positions k+1 onward differ.

Assert:

  max_abs(
    logits_A[:, 0:k+1, :]
    - logits_B[:, 0:k+1, :]

======================================================================
36. REPRODUCIBILITY LEVELS AND ARTIFACT IDENTITY
======================================================================

Three different meanings of "reproduce the model" must be distinguished.

Architecture-equivalent reproduction:

  Implement the equations, dimensions, initialization, tokenizer method,
  data mixture, and training procedure in this paper. This produces the same
  model design and experiment, but random and data-order differences can
  produce different learned weights.

Checkpoint-compatible reproduction:

  In addition to the architecture, use tokenizer files with the SHA-256
  hashes listed in this paper and exactly matching parameter names/shapes.
  This allows strict loading of compatible checkpoints.

Bit-for-bit training reproduction:

  This additionally requires:

  - exact 40,000,000,000-byte token binary;
  - exact SFT JSONL files;
  - exact package and CUDA versions;
  - exact initial RNG state;
  - exact sampler state;
  - exact GPU kernels and deterministic behavior;
  - exact checkpoint from which execution continues.

The Hugging Face streaming calls in the data builder do not pin explicit
dataset commit revisions. If an upstream dataset changes, rebuilding later
can produce different text even with the same dataset identifier. A permanent
archival release should therefore store the completed token binary or its
cryptographic hash and pin every dataset revision.


======================================================================
37. INTERPRETING RESULTS
======================================================================

Training loss measures next-token cross entropy on sampled training windows.
Validation loss measures the same objective on held-out windows. Lower values
are generally better, but they do not directly measure chat usefulness,
truthfulness, reasoning, or safety.

Perplexity is an exponential transformation of cross entropy. A validation
perplexity of 26.40 means that under this tokenizer and held-out sample, the
model's average uncertainty corresponds mathematically to about 26.4 equally
likely alternatives. It must not be compared blindly across models using
different tokenizers or datasets.

The training loss can be lower than validation loss because:

  - weights are optimized on training windows;
  - held-out text can differ in difficulty;
  - each reported train step is one sampled accumulated batch;
  - validation averages a separate fixed set of batches.

Final model quality should be evaluated after all SFT stages with both:

  - deterministic or low-temperature fixed prompts;
  - broader held-out tasks not duplicated in targeted SFT.


======================================================================
38. CONCLUSION
======================================================================

TLGM-1B-1024 is a fully causal, attention-free, approximately one-billion
parameter language model. Its defining operation is a learned
lower-triangular sequence matrix shared across feature channels. Twenty-seven
blocks combine this global position mixing with large token-local feature
MLPs and residual pre-normalized computation.

The model is trained from random initialization with a newly trained
byte-level BPE tokenizer, an exact 20-billion-token corpus, a one-token causal
objective, AdamW, FP16 accumulation, held-out validation, and complete
checkpoint resume. Three assistant-only SFT stages convert the pretrained
continuation model into a small chat model.

The specification, equations, parameter formulas, data quotas, optimizer,
checkpoint contract, code blueprint, hardware setup, shell commands, and
verification checklist in this paper define the complete experiment. An
engineer following them can implement and run an equivalent TLGM-1B-1024
training pipeline without using the original repository.
